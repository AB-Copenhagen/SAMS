## Phase 1: Code-level pieces

- [x] Added `.github/dependabot.yml` — `npm` ecosystem (weekly, grouped minor/patch updates into one PR) and `github-actions` ecosystem (weekly)
- [x] Added `.github/workflows/ci.yml` — on every PR to `main`: `npm ci`, `tsc --noEmit`, `npm run test`, `npm audit --omit=dev --audit-level=high`, Node 26 (matches `@types/node`'s current major)
- [x] Added app-wide security headers in `next.config.js` via a second `headers()` entry with `source: '/((?!embed).*)'` — a path-to-regexp negative-lookahead exclusion, not entry-ordering, because `X-Frame-Options` has no per-origin override value: if the general entry matched `/embed/:token` too, a legacy browser honoring only `X-Frame-Options` (and not the embed-specific CSP override) would still block the one route meant to be frameable. Also set `poweredByHeader: false`.
- [x] Removed the unused `sqlite3` dependency (zero references anywhere in the app) from `package.json`, including its now-dead `overrides` entry (a transitive `undici` pin that only existed because of `sqlite3`'s own `node-gyp` dependency) — `npm install` dropped 50 packages total
- [x] Verified: `tsc --noEmit`, full `vitest` suite (68 tests), and `next build` all pass; empirically confirmed via `next dev` + `curl` that `/login` gets the new general headers (`X-Frame-Options: DENY`, `frame-ancestors 'none'`, `nosniff`, `Referrer-Policy`) while `/embed/[token]` gets only its own `frame-ancestors https://www.ab.dk` — no leakage either direction
