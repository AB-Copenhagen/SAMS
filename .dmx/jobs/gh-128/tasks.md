## Phase 1: Schema & playlist domain logic

- [x] Add `Playlist` (`id`, `name`, `createdBy`, `createdAt`) and `PlaylistItem` (`id`, `playlistId`, `assetId`, `position`, `addedAt`, `addedBy`, unique on `(playlistId, assetId)`) to `prisma/schema.prisma` (mirrors `CollectionAsset`'s join-table shape, with real FKs + `onDelete: Cascade` since both sides are concrete, unlike `EmbedToken`'s polymorphic target), shipped via a new one-shot admin route `app/api/system/migrate-playlist/route.ts` (`CREATE TABLE IF NOT EXISTS`, mirroring `migrate-embed-token`), not a Prisma migration
- [x] Added `lib/playlists.ts` (new file, not folded into `lib/collections.ts` — a playlist has no relation to Collection membership, so its CRUD/ordering concerns are their own domain concern per the project's organize-by-domain `lib/` convention): `createPlaylist`, `listPlaylists`, `getPlaylistWithItems`, `renamePlaylist`, `deletePlaylist`, `assetIsPlaylistEligible` (video-only check), `addPlaylistItem` (throws a descriptive `Error` on a non-video asset or an existing membership, for the Phase 2 route to map to 400/409), `removePlaylistItem`, `reorderPlaylistItems` (whole-list replace in one transaction)
- [x] Extended `EmbedToken`'s `targetType` to accept `'playlist'` (new exported `EmbedTargetType` union in `lib/collections.ts`, used by `generateEmbedToken`/`getOrCreateEmbedToken`); extended `resolveEmbedTarget`/`resolveEmbedAssetTarget` with a playlist branch (loads the playlist's ordered items via `getPlaylistWithItems`, membership-checks a single asset via the `(playlistId, assetId)` unique index) — no `isPublic`/password re-check, consistent with gh-123's resolution design. Added a temporary `if (target.kind === 'playlist') notFound()` guard in `app/embed/[token]/page.tsx` so the now-three-way `EmbedTarget` union still type-checks before Phase 3 builds the real playback branch.

## Phase 3: Playlist embed & self-serve embed UI

- [x] Added `components/EmbedPlaylistPlayer.tsx` (new client component) and wired it into `app/embed/[token]/page.tsx`'s playlist branch (replacing Phase 1's placeholder `notFound()`) — one `<video>` at a time via `VideoPlayer`, advancing with `setIndex` on a new `onEnded` prop added to `VideoPlayer` (previously missing; needed for any "do something when playback finishes" case, not playlist-specific). `autoPlay` only turns on starting with the second item — the first still requires a click, same as today's single-asset embed, consistent with browsers requiring a user-activation before allowing programmatic `play()`.
